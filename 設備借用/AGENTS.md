# 專案規則：工地設備借用登記系統

本資料夾是「工地設備借用登記系統」示範專案。需求以同資料夾的 `需求筆記.txt` 為準，欄位、可選值、權限與交付物都從那裡取用；筆記沒寫的地方標「待確認」，不要自行假設成定案。

## 開工前

- 每次開工，先把工作區更新到 GitHub 上最新的 `main`，再開始修改：

  ```bash
  git fetch origin main
  git checkout -B <工作分支> origin/main
  ```

- 不要在舊版本上繼續改，避免蓋掉別人已合併的內容。

## 金鑰與機密

- 前端只能用 Supabase 的 **publishable key**（`sb_publishable_` 開頭）。它本來就是公開的，可以放進 `config.js` 並上傳。
- **secret key（`sb_secret_` 開頭）與 service_role key 不可以寫進任何檔案**，包括程式碼、設定檔、SQL、文件、測試、commit 訊息與 Pull Request 說明。
- 資料安全靠資料庫的 GRANT 與資料列安全（RLS），不靠隱藏金鑰。資料表開放給前端前，一定要先啟用 RLS。
- 發現檔案裡有 secret key：立刻停止、不要推送，並通知專案負責人到 Supabase 重新產生金鑰。

## 資料

- 範例資料一律虛構：不用真實姓名、電話、工地名稱、客戶資料。
- 已登記的借用資料一律不能修改或刪除（見需求筆記）。

## 完成後

- 用 GitHub 外掛建立 Pull Request，標題用繁體中文，簡短說明做了什麼。
- Pull Request 說明要寫：對應哪一項需求、怎麼驗證的；畫面有變動時附截圖。
- 確認沒有 secret key、沒有真實個資後，用 GitHub 外掛把 Pull Request 合併進 `main`。

## 驗證

- 網頁：送出一筆借用後，要出現在清單上，借出時間由系統產生。
- 權限：未登入時讀不到也寫不進；工地主任登入後可以新增與讀取，修改與刪除會被拒絕。
- 可選值（歸還狀況、狀態）要和需求筆記一致。
